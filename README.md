# Car_Damage_Detection

## Сбор объявлений Auto.ru

Парсер: `code/autoru_parser.py`. Нужны Python 3.10+ и Pillow.

```powershell
python -m pip install -r code/requirements-autoru.txt
python code/autoru_parser.py --limit 1000
```

По умолчанию собираются объявления о легковых автомобилях с пробегом без дополнительных фильтров, со всеми доступными фотографиями. Каталог назначения — `datasets/autoru/` относительно корня проекта. Повторный запуск продолжает сбор, учитывая уже сохранённые объявления и фотографии. Цель `1000` относится к объявлениям с загруженными фотографиями, а не к числу фотографий.

После аварийного завершения запустите ту же команду с тем же каталогом `--output` и параметрами источника. Программа автоматически продолжит текущее объявление с первого недостающего фото, затем обработает оставшуюся очередь и перейдёт к следующей странице выдачи. Заново обходить выдачу с первой страницы не требуется. Автоматический перезапуск самого процесса не выполняется.

Прогресс сохраняется после каждого фото. `checkpoint.json` хранит страницу выдачи и очередь ссылок; `checkpoints/listings/` — состояние объявлений; `checkpoints/photos/` — URL и контрольные суммы фотографий. Эти служебные файлы нужно сохранять вместе с датасетом. Запись идёт во временные файлы с принудительным сбросом буфера на диск и атомарной заменой. При перезапуске восстанавливаются также фото, записанные непосредственно перед падением, но ещё не добавленные в общий JSONL. Незавершённая последняя строка JSONL игнорируется, а соответствия фото и объявлений пересобираются из сохранённого состояния. Файл, скачанный не полностью, загружается повторно.

Файлы результата:

- `images/<listing_id>/<номер>.jpg` (либо `.png`, `.webp`, `.avif`) — исходные файлы фотографий без перекодирования;
- `listings.jsonl` — одна JSON-запись на объявление: URL, текст продавца, цена, характеристики, сведения о продавце и местоположении, комплектация, исходные структурированные данные и список `photos` с относительными путями;
- `image_manifest.jsonl` — одна JSON-запись на фото: `image_path`, `listing_id`, `source_url`, `description`, `vehicle`, `price`, `photo`. Это прямое соответствие фото и описаний;
- `run_summary.json` — целевой объём, фактическое число объявлений/фото и состояние запуска;
- `errors.jsonl` — ошибки доступа, разбора страниц и загрузки изображений.

В `vehicle` предусмотрены марка, модель, поколение, год, пробег, кузов, цвет, двери, двигатель, коробка, привод, руль, состояние, владельцы, ПТС и VIN, если они опубликованы в данных страницы. Доступность полей зависит от объявления. Недоступные значения — `null`. Текст продавца сохраняется отдельно; повреждения не определяются автоматически по фото или ключевым словам. `state_not_beaten` сохраняется только как исходное заявление площадки. Объём двигателя нормализуется в литры, мощность из `tech_param` — в лошадиные силы; исходные поля остаются в `raw_data`.

Поисковую выдачу с фильтрами можно передать через `--start-url`:

```powershell
python code/autoru_parser.py --limit 1000 --start-url "https://auto.ru/moskva/cars/used/"
```

Дополнительные параметры:

- `--urls-file links.txt` — UTF-8, одна ссылка на объявление в строке;
- `--html-dir saved_pages` — разбор сохранённых HTML-страниц; для загрузки фото всё равно нужен доступ к интернету;
- `--cookies <локальный_файл>` — существующая разрешённая пользователем сессия в формате Netscape, если сайт требует входа; файл сессии не копируется в датасет;
- `--max-photos 5` — ограничение количества фото на объявление, по умолчанию все;
- `--delay 2`, `--timeout 25`, `--max-pages 100`, `--start-page 1` — интервал между HTML-запросами, таймаут и границы пагинации;
- `--output <каталог>` — другой каталог назначения.

Парсер читает JSON-состояние страницы (`initial-state`, `__initialState__`, `__NEXT_DATA__`) и JSON-LD. Проверка на реальных страницах в этой среде пока не пройдена: Auto.ru перенаправляет веб-инструмент на вход, прямое HTTPS-подключение завершается таймаутом. Совместимость с текущей разметкой требует проверки после восстановления доступа. Состояние `completed` выставляется только при достижении заданного количества объявлений с фото; при входе, CAPTCHA, HTTP 401/403/429 сбор останавливается и сохраняет промежуточный результат. Код возврата `2` означает, что цель не достигнута.

Проверка на синтетических страницах, без обращения к сети и записи тестовых данных в датасет:

```powershell
python -m unittest discover -s code -p "test_autoru_parser.py" -v
```

## Просмотр датасетов

Для каждого набора создан отдельный ноутбук в `code/viewers/`. Запустите его ячейки сверху вниз; последняя ячейка при повторном запуске показывает новую случайную подборку. Доступны фильтры выборки и класса, количество фото, фиксированное случайное зерно, подписи классов, рамки и контуры.

| Набор | Ноутбук | Разметка и представление |
| --- | --- | --- |
| COCO Car Damage | [viewer_coco_car_damage.ipynb](code/viewers/viewer_coco_car_damage.ipynb) | Повреждения, детали или оба вида COCO-разметки; отдельный просмотр test без аннотаций |
| CarDD | [viewer_cardd.ipynb](code/viewers/viewer_cardd.ipynb) | COCO-полигоны и рамки шести классов повреждений |
| Car Parts | [viewer_car_parts.ipynb](code/viewers/viewer_car_parts.ipynb) | Supervisely, 21 класс деталей, включая внутренние отверстия полигонов |
| Car Damages | [viewer_car_damages.ipynb](code/viewers/viewer_car_damages.ipynb) | Supervisely, восемь типов повреждений |
| Analytics Vidhya | [viewer_analytics_vidya.ipynb](code/viewers/viewer_analytics_vidya.ipynb) | Классы всего изображения из CSV; test без меток |
| data1a | [viewer_data1a.ipynb](code/viewers/viewer_data1a.ipynb) | Классификация damage / whole по названиям папок |
| VehiDE | [viewer_vehide.ipynb](code/viewers/viewer_vehide.ipynb) | VIA-полигоны all_x / all_y и исходные строковые классы |
| Auto.ru | [viewer_autoru.ipynb](code/viewers/viewer_autoru.ipynb) | Фото разных объявлений, описания и раскрывающиеся структурированные сведения |

В локальной копии `car-parts-and-damage-dataset` классы и названия папок перепутаны: `Car damages dataset` содержит детали, `Car parts dataset` — повреждения. Просмотрщики используют фактические классы из `meta.json`. Папки `File1/img/` обоих наборов сейчас пустые: аннотации показываются на сером фоне с явным сообщением об отсутствии фото. Файлы датасетов не изменяются.

Общая отрисовка и адаптеры COCO/Supervisely находятся в `code/viewers/viewer_common.py`; сохраняйте этот файл рядом с ноутбуками. Зависимости: `python -m pip install -r code/viewers/requirements.txt`. Ранее созданный `code/dataset_viewer.ipynb` также сохранён.
